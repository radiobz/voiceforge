## 2. 优化前后基准对比

固定测试文本：2996 字中文（一段自然段落 ×14，含丰富标点）。
经 `chunk_text` 分为 **4 个 chunk**，经 `split_for_tts` 展平为 **98 个并行合成单元（piece）**。
引擎：Edge-TTS（在线），voice=zh-CN-XiaoxiaoNeural，with_subtitle=true。

### 2.1 长文本 TTS

| 指标 | 优化前 | 优化后 | 说明 |
|------|--------|--------|------|
| 文本字数 | 2996 | 2996 | 同一文本 |
| chunk 数 | 4 | 4 | 不变 |
| piece 数（并行单元） | 98 | 98 | 不变 |
| 并发数 | 1（串行） | **6**（VFORGE_TTS_CONCURRENCY 默认） | 有界并发 |
| **总耗时** | **154.5 s** | **28.1 s** | **加速比 ≈ 5.5×** |
| 输出音频时长 | 604.2 s | 604.2 s | 完全一致 |
| SRT 条目数 | 98 | 98 | 时间轴连续无重叠 |
| segments 数 | 4 | 4 | 一致 |

### 2.2 音乐生成

| 指标 | 优化前 | 优化后 | 说明 |
|------|--------|--------|------|
| mode / duration | chill / 120s | chill / 120s | 同参数 |
| 总耗时 | 3.8 s | 4.0 s | CPU 渲染，无加速；但不再阻塞事件循环 |
| .wav 中间残留 | 无 | 无 | finally 清理保持 |

> 说明：音乐生成本身是 CPU 密集（numpy 渲染 WAV + ffmpeg 转码），`to_thread` 不缩短其墙钟时间，价值在于把它移出事件循环，使其与其他请求/TTS 并发时不再互相阻塞。

## 4. 并发参数说明

- 配置项：`TTS_CONCURRENCY`（`backend/app/config.py`）
- 环境变量：`VFORGE_TTS_CONCURRENCY`
- 默认值：**6**
- 可调范围：建议 **2 ~ 16**。
  - Edge-TTS 为免费在线端点，并发过高可能触发限流（403/超时）；过低则无加速。
  - 生产/公网建议 4~6；本地网络良好可尝试 8~10。
- 实现：`asyncio.Semaphore(TTS_CONCURRENCY)` 懒加载（避免模块导入时无事件循环），每个 piece 在 `_synth_piece` 内部 `async with semaphore` 获取许可，`asyncio.gather` 启动全部作业、由信号量限流。

## 5. 遗留风险与限制

1. **ffmpeg 子进程取消不立即终止**：`asyncio.to_thread` 运行的 ffmpeg 子进程在任务 `cancel()` 时不会被立即 SIGKILL；取消信号在 await 点抛出 `CancelledError`，但已派发的 ffmpeg 子进程/线程会继续跑到自然结束。任务目录在取消时 `rmtree`，可能与仍在写盘的子进程产生竞态（概率低，且 `ignore_errors=True` 兜底）。
2. **musicgen 线程取消**：`asyncio.to_thread` 中的 numpy CPU 渲染无法被强杀；取消后线程仍会占 CPU 直到渲染块结束，之后写盘时目录已被删除，异常被线程内吞掉。墙钟上取消响应是即时的（任务状态立即变 failed），但 CPU 回收略延迟。
3. **Edge-TTS 端点限流**：并发 6 为实测稳妥值；若服务端收紧策略，可能出现个别 piece 超时（已有 120s 超时保护），此时整个 `gather` 会因某 piece 异常而失败。后续可增加 piece 级重试。
4. **输出顺序**：`asyncio.gather` 保证返回顺序与提交一致，已按 `chunk_idx/piece_idx` 二次归组排序，拼接顺序与原串行版逐字节一致；SRT 时间轴按各 chunk 实际时长累计，零间隙。
5. **voices 缓存为进程内单例**：多 worker 部署时各进程缓存独立，60s TTL 兜底最终一致；自定义音色增删通过主动失效立即收敛。
